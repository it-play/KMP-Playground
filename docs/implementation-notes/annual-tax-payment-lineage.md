# 연간 세금 납부 계보

연간 세금 원장과 납부 고지는 체결·분배 원장에서 매번 같은 값으로 다시 계산한다. 저장 파일의
`PAID` 상태는 계산 결과를 덮는 값이 아니라, 다음 조건을 모두 충족할 때만 canonical 고지에
결합되는 영구 납부 사실이다.

- 고지 ID, 귀속연도, 통화, 세액, 납부기한이 재계산 결과와 정확히 일치한다.
- `paidAt`은 납부기한 이후의 유효 게임 턴이고 현재 시각을 넘지 않는다.
- `accountingSequence`는 체결·분배·기업행동과 공유하는 전역 회계 순번에서 양수이면서 유일하다.
- 미납 상태에는 `paidAt`과 `accountingSequence`가 없고, 0원 세액에는 납부 고지를 만들지 않는다.

법정 5월 31일이 휴일이면 KOFR/KSD와 공유하는 한국 금융업무 달력의 첫 다음 영업일로
납부기한을 이월한다. KRX만 쉬는 연말 폐장일은 금융업무 휴일이 아니므로 국내 체결의 T+2
결제일 계산에서는 제외하지 않는다.

게임 저장 schema 47에서 납부 시각과 회계 순번을 도입했고, 현재 schema 49는 이를 strict exact-field로 읽는다. 복원 시 원장부터
재계산한 뒤 일치하는 납부 사실만 다시 결합한다. 따라서 이미 납부한 세금은 복원 후 다시
차감되지 않으며, 세액이나 상태만 바꾼 저장은 거부된다.

schema 49는 초기 KRW·0 USD에서 체결, 환전, 분배, 납부를 전역 회계 순번대로 재생해 현재
현금을 검증한다. 따라서 canonical `PAID` 고지만 만들고 실제 원화 잔액을 차감하지 않은 저장은
거부된다. 환전 당시 USD/KRW와 호환 디버그 모드가 명시적으로 만든 현금 조정은 역사적 관측
사실 경계이며, 각각 환전 산식 또는 선행 잔액과 strict하게 결박한다.
